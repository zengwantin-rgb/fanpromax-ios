# i5 自动诊断回传

用户已授权在当前项目服务器运行接收服务。源码、测试、模拟请求、IPA 编译与签名仍仅在 GitHub 托管 macOS 执行。工作区服务器只部署接收服务、建立 HTTPS 通道、保存和读取实际诊断；不得在这里运行单元测试、模拟请求或二进制检查。

这是现有内置游戏 IPA 的诊断功能，不是远程控制整个手机的独立常驻 App。游戏运行时记录实际移动窗口、原生限速值、角色/载具状态、相对高度与速度、异常状态，然后由独立异步网络请求每五秒上传一次。没有增加游戏写入、远程命令、动态脚本、任意内存读取入口，也没有自瞄或压枪。i4 的移动策略保持不变，服务器接受移动与实际三倍速度仍未验证。

## 手机使用

安装 i5 游戏 IPA，或替换对应 dylib。点击 F → 连接诊断服务器，粘贴服务器生成的完整配对串（HTTPS 地址、`#`、256 位密钥）。然后打开“自动回传诊断”。看到“服务器已接收 HH:mm:ss”才代表接收端确认收到。数据未到达时会显示重试或配对失效；不能把“正在发送”当作成功。

每次启动游戏默认关闭回传；配对信息保存在本机钥匙串。退到后台暂停，回到前台继续。关闭回传会取消正在进行的请求，已经到达服务器的记录会保留。解除配对会删除本机密钥。无端点或凭据被编译进公开 IPA。配对串不能上传到公开仓库或公开日志。

手机只发送现有模块生成的 `integrated-status.json` 内容，不读取账号凭据、聊天、照片或其他 App。报告不含绝对世界坐标。身份仅为每次启动随机生成的诊断会话 UUID，不是设备 UDID。网络使用系统 TLS 验证、拒绝重定向、拒绝无匹配 report_id 的回执。每次请求不超过 512 KiB，每次只允许一个请求，响应最多 4 KiB，失败退避最长 60 秒。中断时只保留最新快照，长时间断网会丢失超出模块窗口历史的样本，不承诺持续后台运行。

## 接收端

`receiver.py` 仅监听 `127.0.0.1:18767`，通过单独的 HTTPS 隧道接入。`POST /v1/diagnostics` 需要 Bearer 密钥；没有公网下载诊断的接口。`GET /health` 只返回协议版本。接收端限制请求大小、并发、超时和上传频率；用独立探测密钥接收合成探测数据，探测内容不写入手机日志。

服务以 systemd DynamicUser 身份运行，数据放在 `/var/lib/fanpro-diagnostics/`，目录权限 0700。`latest.json` 是最后收到的手机快照，`reports.sqlite3` 压缩保留最近报告，最多 7 天、2048 条、128 MiB 压缩负载，以先达到者为准。接收端不输出头部、密钥、正文或访客 IP。诊断只能由本机有权限的会话读取；助手不会在会话结束后自行持续分析。

当前没有现成域名时使用独立 Cloudflare Quick Tunnel；它是临时通道，没有稳定性承诺，隧道进程重新创建后地址会变化，需要重新配对。不会修改已有远程连接服务。改成正式域名/固定隧道后，可以在手机更新配对串，无需重新编译。

## 检查范围

托管 macOS 测试包括鉴权拒绝、请求大小、报告格式、非有限值、去重、过期清理、探测数据与手机数据隔离、客户端 HTTPS 配对限制、默认关闭、回执匹配、上传间隔、后台暂停、响应上限、拒绝重定向与 401 自动停止。部署后仅由托管 macOS 用合成数据探测公网 HTTPS。公网探测和模拟器通过不等于手机已连接；实际连通必须以服务器收到 i5 手机报告为准。
